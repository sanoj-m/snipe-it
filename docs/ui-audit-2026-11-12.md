# Killa Asset — UI Inspection Report

**Date:** 2026-11-12 · **Scope:** full killa-v2 theme layer (`public/css/killa-v2*.css`, `killa-ux.css`), layouts, sidebar partial, dashboard views. Read-only audit; no code changed.

## 0. Executive summary

The "shabby" feel is not one problem — it is **four visual languages competing in one app**:

| Language | Where | Canvas | Base font | Page title | Semantic palette |
|---|---|---|---|---|---|
| **killa-v2 "Atelier"** (base) | All classic pages | Cool gray `#f4f5f7` | 12.5px | 17px / 700 | success `#2f9e6e`, warning `#b97d10`, danger `#c0392b`, info `#2470a0` |
| **killa-v2-sidebar pass 2** | Nav rail | (follows base) | 13px rows | — | neutral pill + red bar |
| **killa-ux (.kx)** | Licenses pages (toggle ON) | **Warm cream `#f7f4ee`** | 13px | 22px / 700 hero | success `#2e7d5b`, warning `#8a5f06`, danger `#b03427`, info `#245f86` |
| **k-insights** (in widgets.css) | `/dashboard/insights` | (follows base) | — | 25px / 650 | mono-red metric cards |

Plus upstream AdminLTE 2/Bootstrap 3 underneath, still leaking through in places the overlays miss. Every cross-boundary moment (Licenses toggle, Classic↔Insights switch, any page the overlays don't cover) is a visible seam.

On top of that there are **real defects** (contradictory declarations where the winner depends on load order) and **~500 lines of dead CSS** still shipped to every page.

## 1. Defects (things that are actually broken)

### P0-1. Mixed control heights: select2 36px vs inputs 32px
- `killa-v2.css:782` sets `.form-control { height: 32px }`
- `killa-v2-forms.css:66` re-sets it to **36px**
- `killa-v2-widgets.css:600` re-pins it back to **32px** ("compact scale-down")
- …but the select2 rules in `killa-v2-forms.css` (`min-height: 36px`, `height: 36px`, `line-height: 34px`, arrow 34px, `.input-group-btn > .btn` 36px) are **never re-pinned**.

Net effect: every native input renders 32px tall while every select2 dropdown next to it renders 36px. This is one of the most visible "shabby" signals — mixed-height form rows everywhere. **Pick one (32px) and align select2 + input-group buttons to it.**

### P0-2. `--k-accent-contrast` lives in the wrong file
Used by `killa-v2.css` (checkbox checkmark, radio dot — lines 939/952) and by `killa-v2-dark.css` (datepicker fix, line 694), but **defined in `killa-v2-tables.css:19/32`**. Works only because tables.css happens to always load. The token contract in `killa-v2.css` says shared tokens are single-sourced there — this one violates it. Move it to `killa-v2.css :root` + dark block.

### P0-3. `--k-accent-soft` referenced but never defined
`killa-v2-tables.css:705` uses `var(--k-accent-soft, var(--k-hover-tint))`. The token does not exist in any file — the fallback silently wins. Define it or delete it.

### P0-4. Dark-mode zebra stripes have two sources of truth
- `killa-v2-tables.css:30` sets `--k-table-stripe: rgba(255,255,255,0.03)` for dark
- `killa-v2-dark.css:501-503` paints `.table-striped` rows with `var(--k-row-hover)` (`#20242b`) instead

dark.css loads last and wins, so the tables.css dark token is **dead and misleading**. Pick one mechanism (the token) and delete the other.

### P0-5. Checkbox/radio: two contradictory implementations shipped
- `killa-v2.css:905-965` — full custom skin (`appearance: none`, 14px boxes, CSS checkmark)
- `killa-v2-forms.css:175-193` — "native, no icheck" approach using `accent-color` (dead, because `appearance: none` from killa-v2.css still applies)
- `killa-v2-dark.css:543-546` sets `color-scheme: dark` on checkboxes — pointless under `appearance: none`

Delete the forms.css/dark.css duplicates or delete the custom skin — shipping both is drift waiting to happen.

### P0-6. Placeholder opacity conflict
`killa-v2.css:1110` sets `opacity: 0.75` on placeholders; `killa-v2-forms.css:98` sets `opacity: 1`. forms.css wins. Trivial, but it's the same class of drift as P0-1.

## 2. Dead code & structural drift

### P1-1. ~500 lines of dead sidebar CSS in `killa-v2.css`
The "[killa-v2] CHARCOAL NAV RAIL" block (lines ~1156–1549) styles `.main-sidebar`/`.sidebar-menu`/`.treeview-menu` — markup that **no longer exists**. `layouts/partials/killa-sidebar.blade.php` renders only `.ks-*` classes; the old flyout/corridor mechanics are gone. The 250px width block (lines 1023–1030) is likewise shadowed by `killa-v2-sidebar.css` (256px). This dead block also contains the **old design contract** ("active = SOLID accent rounded rect… the system's ONE flourish") which directly contradicts sidebar pass 2 ("active = NEUTRAL muted pill + 3px accent bar"). Delete it; keep only the header/content margin rules that still apply.

### P1-2. The token single-source rule is already broken everywhere
`killa-v2.css` declares: *"dark overrides live ONLY in killa-v2-dark.css — domain files must not re-define these."* In reality **every domain file** has its own `:root` + dark token blocks (forms:14-24, tables:9-38, widgets:15-23, overlays:9-23). Either enforce the rule or rewrite the comment — right now the comment is a lie that invites P0-2/P0-4-style bugs.

### P1-3. Cross-file token dependencies
`killa-v2-notifications.css` uses `--k-progress-track` (defined in widgets.css). Fragile under any load-order change.

### P1-4. `!important` count: ~241 across the killa-v2 layer
(v2:126, overlays:38, tables:32, dark:20, notifications:17, sidebar:6, forms:2). Some are justified (upstream `overrides.less` forces tenant colors with `!important`), but a quarter of the layer fighting with `!important` makes every future change a specificity gamble. Many could go once the dead sidebar block and tenant-var repairs are consolidated.

### P1-5. Stale references in project docs
`AGENTS.md` and `CUSTOMIZATION_INVENTORY.md` (UI-06) point to `skills/killa-design/SKILL.md` — **that file does not exist**. The actual skill, `skills/killa-design-manual`, documents a *different product* (Killa ERM: React/TypeScript/Tailwind/shadcn, `ThemeEngineContext`, `ConfigPanel`). None of its tokens or rules apply to this Blade/AdminLTE codebase. **This fork currently has no governing design document for its own UI** — which is exactly how the four-language split happened.

## 3. Design-language inconsistencies (the visible "shabby")

1. **Two canvases.** Cool neutral `#f4f5f7` everywhere, except Licenses-with-toggle which flips to warm cream `#f7f4ee` with `#faf7f1` sunken surfaces and `#e7e1d5` borders. Same app, two temperatures.
2. **Duplicate semantic palettes** with close-but-different values (see table above). A green success pill on the Licenses page is *not* the same green as a success alert anywhere else.
3. **Three page-header idioms:** classic `content-header` 17px/700 + breadcrumb pills · Insights 25px/650 + subtitle · kx hero 22px/700 + stat strip.
4. **Two dashboard tile idioms:** classic `k-tile` (per-entity colored icon chips: teal/maroon/orange/purple/yellow/light-blue) vs Insights `k-insights-metric` (mono red chips).
5. **Sidebar status dots** use raw AdminLTE `text-blue/text-green/text-orange/...` colors — outside the killa palette (the CSS comment says this is intentional, but on the neutral rail they read as off-brand noise).
6. **Radius drift:** `--k-radius: 12px` cards vs `--k-radius-sm: 6px` buttons/inputs vs `--k-radius-chip: 10px` dropdowns vs 3px checkbox corners — mostly consistent per-domain, but kx uses 12/6/999 with different shadows, so the *same* Bootstrap markup looks different inside vs outside `.kx`.
7. **Font-size drift:** 12.5px base, 13px sidebar rows, 13px kx, 11px table headers, 10.5px tile labels — no documented type scale.

## 5. Recommended fix order

**P0 — one evening, pure CSS cleanup, zero risk:**
1. Unify control height at 32px: re-pin select2 single/multiple, `.input-group-btn > .btn`, `label.form-control` in one place; delete the losing declarations.
2. Move `--k-accent-contrast` (and `--k-progress-track`) to `killa-v2.css :root` + dark block.
3. Define or delete `--k-accent-soft`.
4. Resolve the dark zebra-stripe duplication (keep the token, drop the dark.css override).
5. Delete the dead checkbox skin in forms.css + the dark `color-scheme` duplicate; fix placeholder opacity in one file.

**P1 — half a day, big payoff:**
6. Delete the dead CHARCOAL NAV RAIL + 250px blocks from `killa-v2.css` (~500 lines gone, smaller payload, no lies in comments).
7. **Decide the ONE design language.** The kx warm-canvas language and the v2 cool-gray language cannot both be "v2". Cheapest coherent path: keep v2's cool neutral canvas (it's everywhere already) and port the kx Licenses pages onto `--k-*` tokens (the kx component *structures* — KPI strip, hero, section cards — are good; only the palette/type tokens need swapping). Alternative: go all-in on warm and re-token v2 — much bigger job.
8. Unify semantic palettes into one token set (`--k-success/warning/danger/info` only; kx maps to them).
9. One page-header pattern (recommend the Insights 25px header as the standard, adapted into `content-header`).

**P2 — hygiene:**
10. New `killa-v2-tokens.css` as the only file allowed to define tokens; enforce "no raw hex outside token blocks".
11. Write the actual design manual for THIS app (replace the Killa-ERM skill content) so the next redesign doesn't fork the language again.
12. Chip away at `!important` after the dead code is gone.
